# 리뷰 작성 도우미

제품 사진과 이름을 넣으면 리뷰에 쓸 만한 **소재를 뽑아주고**, 그중 내가 실제로
겪은 것만 골라서 리뷰 초안을 만들어주는 도구입니다.

핵심은 "AI가 리뷰를 대신 써준다"가 아니라 **"내가 방향을 정하고 AI가 문장으로 옮긴다"**
입니다. 그래서 중간에 사용자가 개입하는 단계가 반드시 들어갑니다.

## 동작 흐름

```
사진 + 제품명
   │
   ├─ (제품명 있을 때) 웹검색으로 사양·평판 수집        ← 그라운딩 호출
   │
   ▼
분석: 사진에서 본 것 / 사양 / 장점 후보 6~8개 / 단점 후보 4~6개   ← 비전 + 구조화 출력
   │
   ▼
[사용자] 겪은 것만 체크 + 구매 이유·겪은 일 서술 + 별점·형식·톤·분량 선택
   │
   ▼
제목 + 본문으로 된 리뷰 1~4편 생성                        ← 작성 호출
```

## 리뷰 형식

실제 쇼핑몰에서 "도움돼요"를 많이 받는 리뷰는 대부분 800자가 넘고 구조가 잡혀
있습니다. 그래서 형식을 골라 쓸 수 있게 했습니다.

| 형식 | 구성 |
|---|---|
| 문단형 | 소제목 없이 자연스러운 문단 2~4개 |
| 구조형 | `구매동기 / 장점 / 단점 / 사용후기 / 총평` 섹션 |
| 요약+상세형 | `✔` 핵심 요약 → 상세 사용기 → 항목별 평가 (음질·휴대성·가성비 등) |

분량은 짧게(200자) / 보통(450자) / 길게(900자) / 아주 길게(1400자) 중에서 고릅니다.
기본값은 '길게' 입니다.

구조형에서 아쉬운 점을 하나도 선택하지 않으면 '단점' 섹션이 통째로 빠집니다.
없는 단점을 지어내지 않습니다.

## 설치

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp env.example.txt .env
# .env 를 열어 GEMINI_API_KEY 를 채웁니다
```

API 키는 [Google AI Studio](https://aistudio.google.com/apikey) 에서 발급합니다.

## 실행

```bash
source .venv/bin/activate
streamlit run app.py
```

## 휴대폰에서 쓰기 (Streamlit Community Cloud 배포)

무료이고, 앱을 따로 설치할 필요 없이 휴대폰 브라우저로 접속합니다.
한 번 배포해두면 URL 을 홈 화면에 추가해서 앱처럼 쓸 수 있습니다.

### 1. 저장소에 올리기

```bash
git init
git remote add origin https://github.com/jayden-code-ai/Review_Auto.git
git add .
git commit -m "리뷰 작성 도우미"
git branch -M main
git push -u origin main
```

`.env` 와 `.streamlit/secrets.toml` 은 `.gitignore` 에 막혀 있어 올라가지 않습니다.
**API 키와 비밀번호가 저장소에 들어가면 안 됩니다.** 올리기 전에 확인하세요.

```bash
git status --short        # .env 가 목록에 없어야 정상
```

### 2. 배포하기

1. [share.streamlit.io](https://share.streamlit.io) 에 GitHub 계정으로 로그인
2. **New app** → 저장소 `jayden-code-ai/Review_Auto`, 브랜치 `main`,
   메인 파일 `app.py` 선택
3. **Advanced settings** → Python version 을 **3.12 이상**으로 지정
4. 같은 화면의 **Secrets** 칸에 아래를 붙여넣고 값을 채웁니다

```toml
GEMINI_API_KEY = "실제_API_키"
APP_PASSWORD = "실제_비밀번호"

RESEARCH_MODEL = "gemini-3.5-flash"
ANALYSIS_MODEL = "gemini-3.6-flash"
WRITER_MODEL = "gemini-3.6-flash"
```

5. **Deploy** 를 누르면 몇 분 뒤 `https://....streamlit.app` 주소가 나옵니다

배포 후에도 Secrets 는 **Manage app → Settings → Secrets** 에서 언제든 바꿀 수 있고,
저장하면 앱이 자동으로 다시 뜹니다.

### 3. 휴대폰 홈 화면에 추가

- **아이폰(Safari)**: 공유 버튼 → "홈 화면에 추가"
- **안드로이드(Chrome)**: 우측 상단 ⋮ → "홈 화면에 추가"

주소창 없이 전체 화면으로 열려서 앱처럼 보입니다.

### 보안

배포된 앱은 URL 만 알면 누구나 열 수 있으므로 **비밀번호 화면이 먼저 뜹니다.**
비밀번호를 통과하기 전에는 본문이 전혀 그려지지 않고, 5회 틀리면 잠깁니다.
`APP_PASSWORD` 가 설정되지 않으면 앱이 아예 열리지 않습니다. 실수로 무방비 상태의
앱이 공개되어 API 요금이 새는 것을 막기 위해서입니다.

비밀번호는 저장소가 아니라 `.env`(로컬) 또는 Secrets(클라우드) 에만 둡니다.

### 다른 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| Streamlit Cloud | 무료, 어디서나 접속, 관리 불필요 | GitHub 필요 |
| 집 와이파이 직접 접속 | 배포 불필요, 외부 노출 없음 | 집 밖에서는 안 됨, PC 가 켜져 있어야 함 |
| Cloudflare Tunnel | 외부 접속 가능, 코드 공개 불필요 | PC 가 항상 켜져 있어야 함 |

집 와이파이 방식은 이렇게 실행한 뒤 휴대폰에서 `http://<PC의 IP>:8501` 로 접속합니다.

```bash
.venv/bin/python -m streamlit run app.py --server.address 0.0.0.0
```

## 자체 점검

API 키 없이 돌아가는 점검 스크립트가 있습니다. 코드를 고친 뒤 돌려보세요.

```bash
.venv/bin/python tests/check.py
```

이미지 축소, 별점 제안 로직, 캐시, **Gemini 스키마 변환**, 그리고 `app.py` 를 실제로
실행하는 UI 렌더링까지 확인합니다. 다만 실제 Gemini 응답 품질은 여기서 검증되지
않습니다. 그건 앱을 띄워서 직접 봐야 합니다.

## 모델 설정

Gemini는 모델 세대 교체가 잦고, API 키마다 접근 가능한 모델이 다릅니다.
그래서 모델 ID를 코드에 박지 않고 `.env` 로 뺐습니다.

| 변수 | 쓰이는 곳 | 기본값 |
|---|---|---|
| `RESEARCH_MODEL` | 상품명 웹검색 | `gemini-3.5-flash` |
| `ANALYSIS_MODEL` | 사진 분석 · 장단점 추출 | `gemini-3.6-flash` |
| `WRITER_MODEL` | 리뷰 문장 작성 | `gemini-3.6-flash` |

셋 다 preview 가 아닌 **안정화 버전**입니다. preview 모델은 이름이 바뀌거나 예고 없이
사라져서 404 를 만들기 때문에 기본값으로 쓰지 않습니다.

**모델 이름은 앱이 시작할 때 자동으로 검증합니다.** `.env` 에 존재하지 않는 이름이
들어 있으면 사이드바에 빨간 경고와 함께 쓸 수 있는 대안 이름이 표시됩니다.
호출을 보내고 404 를 받는 게 아니라, 화면을 그리는 시점에 미리 잡습니다.

전체 목록을 보려면 사이드바 → "문제 해결" → "사용 가능한 모델 확인" 을 누르세요.

`.env` 를 고친 뒤에는 **브라우저 새로고침만 하면 반영됩니다.** 앱을 껐다 켤 필요가
없습니다 (`load_dotenv(override=True)` 로 매 실행마다 다시 읽습니다).

## 구조

```
app.py              Streamlit UI (3단계 화면)
core/
  config.py         .env 로딩, 설정 객체
  schemas.py        Pydantic 모델 = Gemini 구조화 출력 스키마
  prompts.py        프롬프트 3종 (리서치 / 분석 / 작성)
  gemini.py         google-genai 호출 래퍼
  media.py          이미지 축소·해시
  cache.py          분석 결과 디스크 캐시
  analyzer.py       1단계 파이프라인
  writer.py         2단계 파이프라인
```

`core/` 는 Streamlit에 의존하지 않습니다. 나중에 FastAPI를 씌우거나 CLI로 쓸 때
그대로 가져다 쓸 수 있습니다.

## 설계 메모

**왜 호출을 나눴나.** 웹검색(그라운딩)과 구조화 출력(`response_schema`)을 한 번의
호출에 같이 요구하면 모델·버전에 따라 거부되거나 스키마가 깨집니다. 검색은 자유
텍스트로 받고, 그 결과를 다음 호출의 입력으로 넘깁니다.

**왜 근거(basis)를 표시하나.** 장단점마다 `사진 확인 / 검색 근거 / 일반 통념` 중
어디서 나온 판단인지 표시합니다. "일반 통념"으로 뜬 항목은 이 제품에 실제로
해당하는지 사용자가 판단해서 걸러야 한다는 신호입니다. 없는 사양을 지어내는 사고를
막는 가장 값싼 장치입니다.

**왜 별점이 마지막인가.** 별점을 먼저 받고 거기 맞춰 리뷰를 쓰게 하면 순서가
거꾸로입니다. 실제 경험(무엇이 좋았고 아쉬웠는지)을 먼저 고르고, 별점은 그 비율에서
자동 제안됩니다. 물론 슬라이더로 덮어쓸 수 있습니다. 이 방식이면 "5점인데 단점 3개"
같은 모순이 잘 생기지 않습니다.

**"직접 겪은 일" 입력란.** 이 칸을 채우면 리뷰 품질이 가장 크게 올라갑니다.
사진에서 유추한 일반론보다 실제 경험 한 줄이 훨씬 구체적인 문장을 만들어냅니다.
프롬프트에서도 이 내용을 최우선으로 반영하게 지시해뒀습니다.

**캐시.** 같은 사진으로 리뷰를 여러 번 다시 뽑는 게 기본 사용 패턴이라, 비싼
1단계(비전 + 웹검색) 결과를 `.cache/` 에 저장합니다. 톤이나 분량만 바꿔 재생성할 때는
작성 호출 한 번만 나갑니다.

## 앞으로 붙일 것

- **영상 지원** — Gemini는 영상을 프레임 추출 없이 그대로 읽을 수 있습니다.
  `core/media.py` 에 영상 분기를 추가하고 `types.Part.from_bytes` 에 `video/mp4` 를
  넘기면 됩니다. 긴 영상은 Files API 업로드가 필요합니다.
- **리뷰 이력 저장** — 같은 제품에 대해 전에 쓴 리뷰와 문장이 겹치지 않게 하려면
  이력을 남기고 작성 프롬프트에 "이런 표현은 이미 썼다"로 넣어주면 됩니다.
- **FastAPI 분리** — 여러 사람이 쓰게 되면 `core/` 위에 라우터만 씌우면 됩니다.

## 주의

이 도구는 **본인이 실제로 사용한 제품의 리뷰 초안**을 정리하는 용도입니다.
써보지 않은 제품의 리뷰를 만들어 올리는 것은 대부분의 쇼핑몰 약관 위반이고,
전자상거래법상 기만적 표시·광고에 해당할 수 있습니다. 2단계에서 항목을 직접
고르게 만든 것도 그래서입니다. 겪지 않은 항목은 체크하지 마세요.
